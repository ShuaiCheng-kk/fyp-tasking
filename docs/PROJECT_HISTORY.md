## Current build state (Owner module)

Owner sidebar (8 items): Dashboard · Report · Team · Communication (Announcements + Messages) · Inbox · Recruitment · Attendance · Settings.

**Completed (UC-01 → UC-20):**
- Dashboard: manage departments (add/edit/delete), generate invitation codes, assign Manager to department, switch active company.
- Team: view members (grouped by role), remove member, change member's department, change member's reporting manager.
- Communication: post / read / edit own / delete own announcement; send direct message (real-time, cannot message Casual Workers).
- Inbox: accept/decline company invitation.
- Settings: edit company profile, create additional company, delete company, manage subscription plan, leave company.
- Logout.

**Placeholder pages (no functionality yet):** Report, Recruitment, Attendance. Plus the Dashboard Timeline / scheduling / task-allocation work (expands the Dashboard page).

**Build order with dependencies:** Shift first → then Timeline display + date nav → then Task (create/assign/view) → then Attendance (4-tier) → Recruitment → Report → AI features. Don't start Attendance or AI before Shift/Task data exists.

## Decision log

- _2026-06-03_ — Initial constitution. 6 roles (Owner⊇Partner⊇Manager⊇Employee; CW & Guest independent); Shift + Task as two entities (Task belongs to Shift); Owner schedules/assigns directly across all departments on one Timeline; AI limited to the four named features, all built manual-first behind a service function.
- _2026-06-03_ — Timeline lives inside the Dashboard module, not a separate sidebar item.
- _2026-06-03_ — Refinements after Owner walkthrough: (1) Attendance approval is 4-tier, ending in Owner final approval. (2) Employees are scheduled on shifts and assigned tasks like Casual Workers. (3) Task assignment is strictly one level down. (4) Announcement + Message merged into one "Communication" module (two tabs). (5) Import departments (no emails) vs import members (sends invitation emails) — kept separate. (6) Owner can post job openings in Recruitment (Manager inherits this).
- _2026-06-03_ — Added diagram-friendly code conventions so teammates can draw MVC class & sequence diagrams directly from the code.

## Key learnings

- Defining business logic is harder than implementation — clarify rules/edge cases before coding.
- Bugs scale with codebase complexity — test section by section (build → test → fix → push).
- Session/cookie timing is a recurring auth bug source.
- Supabase FK ordering matters (`used_by` before user row caused a constraint violation).
- Documentation after code: feature log and Technical Manual generated by reading the finished codebase.
